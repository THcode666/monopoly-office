# 局域网联机 · 简要步骤

游戏支持三种联机方式，启动时会**自动按 WebRTC → WebSocket → 伪联机** 顺序降级。

---

## 一、伪联机（无需任何网络，最稳）

任何环境下都能用，包括断网、浏览器限制、公司网络隔离。

### 步骤

1. 所有人都打开游戏，选 **局域网对战**，取同一个 4 位房号（如 `A3F9`）。
2. 轮到谁，谁就点右下角 **「导出回合包」**，会下载一个 `turn-12.json`。
3. 用任意方式把这个文件发给下一位（微信、U 盘、邮件都行）。
4. 接收方点 **「导入回合包」** 选文件。
   - 校验通过 → 状态衔接，可以继续玩
   - 校验失败 → 提示"状态不一致或已被篡改"，需要重新导出
5. 重复 2~4 直到游戏结束。

### 校验做了什么

每个回合包带一个 `stateHash`（FNV-1a 哈希）。导入方会：
1. 从上次的 action 日志重放到当前状态
2. 计算哈希并与包里的比对
3. 不一致就拒绝

**能防**：文件损坏、被改过、版本不符。
**不能防**：接收方自己改 actions 后重新导出（这是"友战模式"，界面里已注明不保证公平性）。

---

## 二、WebSocket（同一局域网，推荐）

需要一台机器跑中继服务。**不需要外网**。

### 步骤

1. 在项目目录运行：

```bash
node server/room-server.js
```

（默认端口 8974，可 `PORT=9000 node server/room-server.js` 改）

2. 房主在游戏里选「局域网对战」，填写 4 位房号，点 **「我要建房间」**，
   中继地址填 `ws://127.0.0.1:8974`（其他机器填房主的局域网 IP，如 `ws://192.168.1.20:8974`）。
3. 其他人在同一页面填**同样的房号**，点「我要加入房间」。

### 注意

- Windows 防火墙会拦截未授权的 Node 进程，首次运行需要允许（选「专用网络」即可）。
- 房主和客机必须在同一网段（公司 Wi-Fi 常有 AP 隔离，改用手机热点最稳）。

---

## 三、WebRTC P2P（延迟最低）

无服务器，但需要**手动交换一次握手码**（复制粘贴）。

### 步骤

1. 房主点「创建连接」，生成一段 **邀请码**（offer），发给客机。
2. 客机粘贴邀请码，点「生成回执」，得到一段 **回执码**（answer），发回房主。
3. 房主粘贴回执码，点「完成连接」。

之后就是直连 P2P，不经过任何服务器。

### 注意

- 只在首次需要握手，游戏过程中不打扰。
- 交换码比较长（几百字符），用微信传比较方便。
- 部分网络（对称 NAT）下打洞失败，会自动降级到 WebSocket。

## 四、断线重连

| 情况 | 表现 | 恢复 |
|---|---|---|
| 客机掉线 | 面板显示"掉线中，AI 暂代操作" | 客机重连后自动 `SYNC_REQ`，host 按 seq 差补发增量或全量 |
| 客机掉线超过 9 秒 | Host 标记离线，AI 接管该座位 | 重连即恢复 |
| 房主掉线 | 30 秒无响应后进入选举 | 任意客机本地重放出等价状态 → 投票推举新房主 |
| 房主迁移失败 | 无法选出新房主 | 自动降级为伪联机，游戏可继续 |

**房主能掉线不丢进度**，是因为 reducer 是纯函数、action 日志在 state 里，
任何客户端都能在本地重放出完全相同的状态。这是第 1 步架构设计的直接收益。

## 五、消息协议（供二次开发）

统一信封：`{ v: 1, room, seq, type, payload }`

| type | 方向 | 时机 |
|---|---|---|
| `HELLO` | 客机→房主 | 连接建立，带 lastSeq 用于增量同步 |
| `WELCOME` | 房主→客机 | 握手成功，分配座位 + 全量状态 |
| `ROOM_STATE` | 房主→全部 | 每次变更后广播 |
| `ACTION` | 客机→房主 | 玩家操作 |
| `REJECT` | 房主→客机 | 非法操作（如抢跑、非本人回合）|
| `PING` / `PONG` | 双向 | 每 3 秒心跳 |
| `SYNC_REQ` | 客机→房主 | 重连时带 lastSeq |
| `CANDIDATE` / `VOTE` | 双向 | 房主迁移选举 |
| `HOST_MIGRATE` | 房主→客机 | 通知新房主 |
| `BYE` | 双向 | 主动退出 |

**防作弊**：客机只发 action，规则由 host 跑 reducer 判定。
客机即使伪造 action 也会被 host 重放驳回（`REJECT`）。

## 六、常见问题

**Q：连不上？**
按这个顺序排查：① 是不是同一个房号；② 防火墙有没有放行；③ 是不是同网段；
④ 用手机热点试一下（排除公司 Wi-Fi 的 AP 隔离）。

**Q：能改数值吗？**
可以，而且所有人必须用**同一份** `data/*.json`。不一致会导致回合包校验失败。
详见《如何自定义数值与文案》。

**Q：房主崩了游戏怎么办？**
不用重开。等客机重新选举出新房主（会自动发生），或降级到伪联机模式继续。
